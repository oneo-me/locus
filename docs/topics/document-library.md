# 文档库

验证记录只覆盖已注明的测试范围与反馈对象；未注明适用提交的既有记录，其代码版本未知，不代表当前版本重新通过验证。

当前需求清单见[需求](../requirements.md)。本篇维护详细定义与适用验收边界。

## 目标

文档库让用户和 Agent 围绕同一套本地 Markdown 文件工作。它拥有内容模型、文件边界和可重建投影，不拥有窗口布局、用户偏好、Agent runtime 或终端进程。

## 对象与规则

- 文档库是用户选择的本地根目录。
- 非隐藏目录中的 `index.md` 定义一篇笔记；目录层级定义笔记层级，缺少 `index.md` 的目录可以只组织后代。
- 笔记标题、图标、概要和归档状态来自 YAML frontmatter；标题缺失时可以回退到目录名。其他 frontmatter 字段作为自定义元数据保留和呈现。
- `assets/` 存放笔记附件；`assets/icon.png` 是专用图标，不计为附件。`canvas/` 存放画布入口及资源。`assets`、`canvas` 是保留目录名，不允许作为笔记或组织目录；扫描不把它们的内容识别为子笔记。笔记路径排除符号链接、隐藏目录和 `node_modules`。
- `locus://<库内路径>` 是正式库内地址；空格、百分号与井号可编码，导航、完整 MCP 和画布组件统一解码一次并拒绝编码的分隔符和父目录。标准 Markdown 链接用于正文引用，目标解析不得越过文档库边界。
- 显式归档笔记及其后代不进入普通导航；设置中仍可发现显式归档项并逐项恢复。

Markdown、画布与附件文件是内容事实。标题、导航、搜索、关系、附件数量、Git 状态和缩略图都是从文件派生的视图，不得反向成为权威数据。

## 导航与阅读

导航以目录层级呈现笔记，支持选择、展开、同级排序、附件数量和 Git 变化提示。自定义同级顺序独立保存，不修改文档库内容；未记录的路径按稳定路径顺序补入。

选择笔记后才读取该笔记完整 `index.md` 并移除 frontmatter 交给 Markdown 渲染。普通笔记阅读页呈现标题、图标、概要、自定义元数据、正文和附件扩展；自定义 YAML 字段使用 GPUI Kit DescriptionList，单列横向排列，不显示组件边框、分隔线或标签背景，沿用现有容器与文字样式；标签按实际显示字体、字号和字重测量最长 key 并统一对齐，key 保持单行，不限制标签列占宽比例；缩小属性行上下留白，值允许换行。对象递归展开为子属性列表，每层分别自动计算 key 列宽；数组按原顺序从 1 编号，混合数组及对象、数组相互嵌套均逐层显示。空对象、空数组与 null 分别显示为 `{}`、`[]`、`null`，字符串保留原值和换行，不把复杂值序列化为 JSON 正文。概要与元数据共同位于正文头部，普通笔记内容顶部留白为 3.5 rem（默认字号下 56px），缩短与标题区域的距离；支持复制正式引用、使用外部编辑器打开文件、在文件管理器中显示目录、归档和更新图标。

Markdown 通过 GPUI Kit TextView 呈现常规块与行内语义、表格、图片和库内链接，支持连续文本选择、全选及复制；代码正文完整显示并参与文本选择，不提供代码块专用复制按钮或展开收起。`gallery` 与 `attachments` 扩展只接受当前笔记拥有的安全本地文件；无效内容显示可读错误，不访问领域边界外的路径。

## 笔记快捷入口

YAML frontmatter 的 `shortcuts` 提供 `website`、`github`、`directory` 三个可选字符串字段。网站和 GitHub 使用默认浏览器打开，仅接受 HTTP(S) 地址；目录复用笔记编辑器偏好，VS Code 打开目录，系统默认交由系统打开目录。标题栏显示有效入口，顺序为复制引用、网站、GitHub、打开项目、笔记菜单；打开项目紧邻菜单之前，采用 FolderPen（文件夹与笔）图标表达编辑项目。VS Code 配置下提示为“在 VS Code 中打开项目”。“编辑笔记”与“打开笔记所在目录”收纳到笔记菜单中。命令面板提供同一组操作；提示显示目标，继承入口补充来源笔记。目录入口与原有“打开笔记所在目录”是不同操作。

```yaml
shortcuts:
  website: https://example.com
  github: https://github.com/example/project
  directory: ~/Projects/example
```

当前笔记没有 `shortcuts` 时，沿目录层级取最近一个定义该字段的祖先笔记，跳过纯组织目录。配置按整组覆盖，不逐字段合并；`shortcuts: null` 阻断当前笔记及未自行定义该字段的后代继承，`shortcuts: {}` 定义空组。组内省略或为 `null` 的字段不显示入口。标题、概要及其他自定义属性不继承。

继承是可重建投影，不复制到子笔记文件。无效配置仍形成继承边界，不回退祖先；有效字段继续可用，无效项在标题栏提示并由 MCP 返回诊断。父笔记保存后通过已有文件观察刷新入口；移动笔记后按新层级重新求值，不自动改写配置。

目录支持绝对路径、`~/` 与相对路径，相对路径始终基于定义该配置的笔记目录，`~/` 指运行应用的本机用户目录。目录可以位于文档库外，点击时检查存在且确实是目录，在后台调用外部编辑器，失败显示错误；不执行 Shell 表达式，也不自动创建目录。移动笔记前需检查相对目录与继承来源的变化。

标准与完整 MCP 均将本地配置与生效结果分开返回，具体字段见[Agent 接入](agent-access.md)。

## 画布

笔记以 canvas/index.html 或互斥的 canvas/index.json 标识唯一所属画布，扫描检查入口存在性，不执行源码。canvas 与 assets 为保留目录，画布文件不计入附件；安装的 node_modules 不作为笔记资源或库变化通知。画布存在时替换标题与元数据以下的阅读区域，无画布时显示正文。完整运行、复用与资源契约见[画布](canvas.md)，原生布局与命令见[桌面工作区](workspace.md)。

## 文件变化与冲突

应用启动或切换文档库时建立不长期保存全部正文的内存投影，并以相同边界递归观察文件。相关事件短暂合并后在后台完整重建导航树，不直接按单条事件修改派生状态；无法可靠定位路径时执行全量核对。笔记或附件创建、删除和归档通过同一批次刷新投影。

当前笔记相关文件变化时后台重新读取正文，期间保留已有内容和阅读位置；笔记删除、归档或不再有效时清除选择与正文。旧文档库或旧选择的迟到任务不得覆盖当前状态。观察失败时保留最后一次成功投影并暴露错误，不用轮询伪装为最新状态。

文件内容与缓存、外部写入或用户操作冲突时优先暴露真实状态，不静默覆盖较新的文件。归档、恢复和图标更新必须原子维护真实文件，保留无关 frontmatter、正文、BOM 与换行风格；无法安全修改时拒绝写入。

## Git 与附件

Git 状态以文档库根目录为仓库边界，把 `index.md`、`canvas/` 和 `assets/` 下任意层级文件的变化归并到所属笔记，并向祖先汇总后代变化。文档库不是 Git 根仓库或 Git 不可用时，只影响变化提示，不阻断阅读。

本地位图可以生成等比缩略图和笔记图标。缩略图与远端链接图标属于可重建缓存，不写入文档库；上传笔记图标时写入当前笔记的 `assets/icon.png` 并同步 frontmatter，不能覆盖符号链接或非普通文件。

## 接口与依赖

- [桌面工作区](workspace.md)消费导航、当前正文和明确的归档、恢复、图标更新操作。
- [Agent 接入](agent-access.md)复用同一内容模型；标准入口发现文件，完整入口通过逻辑地址直接读取和维护真实文件，工具与冲突规则见对应专题。
- [文档库终端](terminal.md)只取得当前文档库根目录，不读取或修改领域状态。
- `source/crates/locus-library/src/`负责扫描、读取、修改、Git 投影与文件观察，并保持对 GPUI 的独立。
- GPUI Kit TextView 负责通用 Markdown 解析、排版与选择；`source/crates/locus-ui/src/markdown_extensions/` 通过扩展接口接入图库、附件、图片、链接图标和平台行为。

领域变更至少验证路径规范化、边界穿越、frontmatter 保真、归档、图标写入、创建删除刷新、Git 归并、文件事件批次、当前正文刷新和迟到任务隔离。

快捷入口验证（部分验证）：`cargo test -p locus-library -p locus-mcp -p locus-ui -p locus-workspace --locked --offline` 通过 45、16、17、39 项测试。用例覆盖最近祖先、纯组织目录、整组覆盖、null 阻断及后代自行覆盖、空组、来源地址编码、相对目录基准、父配置刷新、非法值与原始文件不被写回；标准三工具和完整接口返回相同来源与生效值。实际工具栏、命令面板操作、浏览器与编辑器启动待用户验证。

多层 YAML 验证（部分验证）：新版依赖上的工作区 40 项测试通过，覆盖对象子属性、对象数组、嵌套混合数组、数组编号顺序、空对象、空数组、null 及多行字符串。层级递归由应用生成 DescriptionList，组件不直接解析 YAML。测量使用实际显示字体，标签列宽按内容计算以保持 key 单行，属性行距紧凑；实际排版待用户验证；依赖与全工作区验证见[工程](../engineering.md)。

TextView 阅读验证（部分验证）：`locus-ui` 的扩展语法与 UI 集成测试覆盖图库、附件引用和安全路径校验，正文、表格、任务列表及长代码块的全选与复制，扩展声明源码排除，正文更新，以及内部链接和引用式外部链接的鼠标、键盘激活。`locus-workspace` 测试覆盖代码字体向框架主题投影及明暗主题切换后的保留。实际打开含中文、表格、长代码、图库、附件和链接图标的笔记，检查窄窗口换行、图片尺寸、跨段落拖选、滚动时选择与笔记切换；代码块应完整显示且没有复制或展开收起按钮。实际阅读已发现中文混排和表格文字右侧裁切，尚未修复，复现与测量依据见[工程](../engineering.md)；其余视觉和实际操作体验待验证。
