# Locus

## 产品定义

### 核心承诺

知识内容始终属于用户，并以用户可直接访问、编辑和版本管理的本地文件为唯一事实来源。Locus 为人提供适合长期阅读、组织与审阅的工作台，为 Agent 提供明确的知识发现与笔记库操作入口，不在两者之间建立需要同步的专有副本。

Locus 首先服务在个人设备或私有环境中长期维护知识的独立开发者、创作者和一人团队，帮助他们：

- 快速定位、阅读和理解层级化知识及其关系。
- 在不迁移内容或托管副本的前提下，让现有 Agent 使用同一套知识。
- 看清外部编辑器或 Agent 对真实文件造成的变化，并继续使用熟悉的编辑器与 Git 管理内容。

### 产品模型

- **文档库**：用户选择的本地 Markdown 根目录，是内容、层级与本地工作上下文的边界。
- **笔记**：由目录中的 `index.md` 表达的知识单元，可以拥有子笔记、元数据、一个画布和附件。
- **画布**：由笔记的 HTML 与 JavaScript 表达的交互内容，Agent 通过源码维护，支持 JSON 数据调用共用模版与导出，独占标题栏及头部元数据以下的内容区。
- **附件**：保存在笔记 `assets/` 目录并由该笔记拥有的普通文件，不包含笔记、图标或画布文件。
- **派生视图**：从真实文件重建的导航、搜索、关系和 Git 状态，不拥有内容事实。
- **外部客户端**：通过标准 MCP 接口定位原始文件，或通过完整 MCP 接口直接操作同一笔记库的 Agent 或其他工具。

文档库拥有笔记，笔记形成层级并拥有附件；笔记之间通过标准 Markdown 链接与 `locus://` 地址建立关系。界面、外部编辑器与 Agent 共同作用于同一套文件。

### 能力与流程

- **知识工作**：定位、阅读、组织、归档、恢复和审阅 Markdown 知识及其附件与关系，详见[文档库](topics/document-library.md)。
- **桌面工作台**：在原生窗口中组合文档导航、当前内容、设置与本地工作上下文，详见[桌面工作区](topics/workspace.md)。
- **本地操作**：在当前文档库根目录调用用户选择的外部终端与 Agent，详见[文档库终端](topics/terminal.md)。
- **Agent 接入**：按层级、关键词或逻辑地址发现笔记，并选择文件工具协作或完整 MCP 笔记库操作，详见[Agent 接入](topics/agent-access.md)。

用户选择文档库后，Locus 从真实文件建立可重建的导航与状态投影；用户通过导航、搜索或笔记链接定位内容并阅读或组织笔记。用户、编辑器或 Agent 修改文件后，Locus 重新读取变化并更新派生视图。标准 MCP 接口返回原始路径，供具备本机文件访问能力的客户端协作；完整 MCP 接口通过逻辑地址读取和维护笔记、附件、图标与画布，客户端不需要访问服务端磁盘。两个入口共享同一服务、文档库和局域网设置，不建立内容副本。

### 产品原则

- **本地优先**：内容、设置与派生状态默认保存在用户自己的设备或私有环境中。
- **单一内容事实**：Markdown 文档树是知识内容的唯一权威，不建立托管副本或平行内容模型。
- **原生文件协作**：文件工具和完整 MCP 操作共同维护真实文档树；MCP 只提供笔记库范围内的操作，不扩展为通用文件系统、版本控制或权限平台。
- **派生状态可重建**：导航、搜索、关系与 Git 状态都能从真实文件重新生成。
- **状态真实**：只呈现已经读取或可以核查的内容、关系与变化，不生成假进度或虚构事实。
- **显式破坏**：删除、覆盖、回退与 Git 操作必须来自用户明确意图，并说明对象、范围与影响。

### 范围与取舍

Locus 提供本地 Markdown 的阅读、组织、检索、链接浏览、变化审阅及 Agent 发现与操作入口。它不成为通用富文本 CMS、云同步服务、多人权限平台或模型提供商。

Agent 会话控制可以在复用成熟 runtime 且忠实保留其权限、认证和能力边界时扩展；Locus 不自行拥有 Agent loop、模型 API、提示系统、skills、memory 或通用工具权限模型。外部 Agent 可能按自身配置把内容发送给远程服务，其账户、模型、密钥、数据策略和计费不由 Locus 控制。

Locus 选择可直接访问的 Markdown，而不是更强封装但造成锁定的内容模型；选择通过标准发现与完整操作两个 MCP 入口支持客户端协作，保持笔记库边界与单一文件事实；选择可核查的真实状态，而不是用自动摘要或模拟进度制造表面统一。

## 视觉规范

### 设计方向

Locus 的体验声音是克制、清晰、可信。界面清透、安静，以内容理解和精确操作为中心，适合长期高频使用，不呈现为 SaaS dashboard、营销站、终端皮肤或普通聊天壳。

“安静”表示界面不争夺内容注意力，“清晰”表示对象、状态与下一步无需猜测，“可信”表示所有反馈都对应可核查事实。主要焦点始终是当前内容或当前任务；导航、状态与派生活动按需退居辅助层。

### 视觉与组件语言

- 主题、色彩、字体、圆角、阴影和状态使用 `gpui_kit::component::Theme` 的语义 token，页面不建立平行 token 体系；具体数值以共享实现为准。
- 通过留白、对齐、文字权重、克制色面和低对比边界建立层级。强调色只用于主要操作、当前选择、焦点和确有语义的状态。
- 共享组件、图标、滚动条和窗口根容器以 `gpui_kit::component` 为基线；现有能力无法表达稳定产品行为时才建立小型组合组件。
- 卡片只用于真实独立对象或需要抬升的层级；状态色必须配合文字、图标或可访问名称，不能单独承担含义。
- 图标采用统一图标族与尺寸，不使用近似自绘图形、装饰 Emoji、霓虹、渐变文字或无信息作用的动效制造“智能感”。
- 本地路径、长标题、代码、表格和本地化文本必须安全换行或截断，不得造成页面级横向溢出。
- 窗口以平台原生材质提供环境层，macOS 使用系统 Sidebar，Windows 的材质与窗口操作遵循[桌面工作区](topics/workspace.md)的共享约定；笔记页面、设置内容区、菜单和浮层使用稳定的不透明语义表面保证阅读对比度；Windows 工作区与设置侧栏透出原生 Mica。

### 交互与状态

- 使用熟悉的桌面交互与原生语义；品牌表达不能改变控件的可预期行为。
- 设置在当前主窗口内替换工作区，返回后恢复原工作区和焦点，不创建平行应用状态。
- 中文与英文保持同一信息层级和控件结构；切换语言时同步应用文案、组件 locale 与原生菜单。
- 加载、空白、错误、断连、禁用、选中、冲突与完成必须真实、可区分，并说明影响和可用动作。
- 破坏性操作、外部权限及可能把内容交给远程服务的行为，在执行前说明对象、范围和影响。
- 动效只表达反馈、状态或空间变化，不覆盖输入或阅读位置，并尊重系统的减少动态效果设置。

### 视口与可访问性

当前产品维护桌面窗口结构，不承诺移动端、平板、触摸手势或响应式重排，但必须处理窗口缩放、长短内容、溢出和浮层边界。

所有功能以 WCAG AA 为底线，提供完整键盘路径、可见焦点、逻辑 Tab 顺序、足够对比度以及屏幕阅读器可理解的名称与状态。关键操作不能只依赖 hover、颜色或动画。

用户始终应能判断当前文档库、当前内容、操作对象和持久化结果。文件内容与派生视图不一致时优先暴露冲突；空状态指向下一步，错误说明问题、影响和恢复动作；本机资源、外部编辑器与 Agent 的边界始终可见。
