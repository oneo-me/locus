# 内嵌终端

## 适用范围

本篇保留共享 `oneo-gpui-terminal` 的选型依据。当前 Locus 产品通过外部终端启动 Agent，不把内嵌终端作为当前用户流程。

## 问题

共享终端组件需要在 GPUI 原生界面中提供真实终端，同时保持单进程架构、原生焦点与输入路径，并避免自行实现完整 VT 状态机。

## 参考与事实

参考 Waku 的 `src/terminal.rs`；原调研未记录可公开核验的仓库地址与版本。Waku 使用 `alacritty_terminal` 承接 PTY 生命周期、VT 状态机、滚动历史、选择、控制序列和可见网格，再把网格转换为 GPUI 文本；这证明 GPUI 表面不依赖 WebView 也能提供交互终端。

`alacritty_terminal` 已处理控制序列、宽字符、颜色、选择、窗口尺寸和进程生命周期。Locus 仍需负责网格到 GPUI 的绘制映射、键鼠输入、原生文本输入桥接、焦点和刷新调度。

## 方案比较

- **自行实现 PTY 与 VT**：会重复成熟终端核心已经解决的协议与平台问题，正确性和维护成本最高。
- **WebView 终端**：需要 JavaScript 渲染器、进程桥接以及另一套焦点、剪贴板、主题和尺寸同步边界，与当前原生单进程基线冲突。
- **Alacritty 核心 + GPUI 视图**：复用成熟 PTY 与状态机，并把产品交互留在现有 Rust 和 GPUI 边界内，整体复杂度最低。

## 结论

采用 `alacritty_terminal` 0.26，关闭默认 features，只使用终端状态与平台 PTY。共享 crate 保留会话、ANSI 调色板、输入、选择和网格快照，不引入当前产品不需要的 URL 探测、上下文菜单或项目模型。

宽字符本体依靠字体占据两个单元格，后继 `WIDE_CHAR_SPACER` 不生成额外文本。终端通过 GPUI 原生文本输入接口接收输入法组合与提交事件：组合态只显示在光标处，提交态才写入 PTY；控制组合键继续按终端协议编码。

共享终端组件接受调用方提供的中性配置；当前 Locus 的外部终端产品边界见[文档库终端](../topics/terminal.md)。
