# Library terminal

This document owns current behavior, implementation boundaries, and acceptance requirements.

## Purpose

Users launch installed Agents from the current knowledge workspace to work at the same library root. Locus selects only the terminal, Agent, shell, and launch directory. External software owns terminal appearance, sessions, authentication, models, permissions, and process lifecycle.

## Product behavior

- Terminal settings offers the system terminal and Ghostty; Windows offers only the system terminal. The system terminal is the default.
- Shell choices on Unix are Default, zsh, bash, and fish. Default preserves `/bin/zsh` on macOS and `/bin/sh` on other Unix platforms. Explicit choices search absolute directories in the app's `PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, and `/bin`, accepting executable files only. An unavailable shell produces a launch error; it never silently falls back. Install fish 3.0 or later for the launch script's `&&` syntax. Windows retains `cmd.exe` and has no Shell control.
- Agent choices are Codex, pi, OpenCode, and Claude Code, with Codex as the default. Commands are `codex`, `pi`, `opencode`, and `claude`, without unspecified initialization commands, arguments, or prompts.
- The shortcut remains Command+backtick, or the corresponding Control combination on other platforms. The command palette offers the same Open Agent… action. Each press triggers once; holding the key does not repeatedly create windows. Duplicate submissions are rejected during launch handoff. The shortcut also works with canvas focus.
- The launch directory is always the current library root captured at activation, not the current note directory. The command is disabled without a library; an invalid directory produces an error. Opening a terminal does not switch the Locus page or expand a sidebar.
- On macOS, the system terminal is Terminal. Ghostty uses the AppleScript interface in version 1.3.0 or later. Each operation requests one Agent session and reuses a running app. Terminal creates a new window; Ghostty creates a tab in the most recently used existing window or creates a window if none exists. It does not type commands into existing sessions. The selected shell loads login and interactive configuration to resolve installed Agents (the other-Unix Default retains login-only startup). The same shell remains available if an Agent exits or its command cannot be found.
- Users install the terminal and Agent first. Terminal launch failures appear in app notifications. Agent command, authentication, and runtime errors appear in the external terminal. Locus does not describe a terminal handoff as successful Agent execution.
- Locus does not save, close, or restart opened external sessions. Library switches, selection changes, and quitting do not affect them. Subsequent launches use the new selection.
- Preferences store external terminal, Agent, and `agent_shell` selections. Missing `agent_shell` uses Default; the obsolete embedded `terminal_shell` field is not reused. Old embedded-terminal fields do not participate in current configuration. Reading old TOML preserves other valid preferences; normal saves remove fields outside the type.

## Implementation boundaries and acceptance

`locus-preferences` defines terminal, Agent, and shell choices; the settings entity owns the sole runtime selection. `locus-workspace/src/workspace/terminal.rs` owns actions, background handoff, duplicate-submit protection, and failure notifications. `locus-ui/src/platform/terminal.rs` owns platform commands and path quoting. Locus uses external terminals.

Both macOS terminals first receive AppleScript `launch`, then create a session, then `activate`, avoiding a default window from normal startup. Terminal uses `do script`. Ghostty uses `new surface configuration` with `initial working directory` and `command`, then `new tab in front window with configuration` when a window exists or `new window with configuration` otherwise. Directories and commands pass through separate arguments and quoting that preserves literal text in POSIX shells and fish, including backslashes and single quotes. See [Apple's launch definition](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html) and [Ghostty AppleScript documentation](https://ghostty.org/docs/features/applescript). Ghostty's normal session restoration follows user configuration; Locus does not modify terminal settings or close existing windows. Windows runs Agents in new system consoles. Users verify target-platform launching, system authorization, shell configuration, and Agent installation. Do not automatically launch terminals or Agents for acceptance testing.

Acceptance covers terminal, Agent, and shell preference persistence; login configuration and post-Agent shell behavior for zsh, bash, and fish; missing-shell notifications; removal of old fields while retaining valid preferences; missing or invalid libraries; paths containing Chinese, spaces, quotes, newlines, and shell special characters; actual launch directories and commands; exactly one new Agent session when terminals are stopped, running, or running without windows; Ghostty tabs without additional windows, use of the most recently used window among several, and exactly one new window when none exists; preservation of existing sessions; one activation per held key; canvas-focused shortcuts; missing terminals, missing Agents, and exit behavior; and settings or library switches affecting only subsequent sessions.

Run `cargo test -p locus-ui --locked platform::terminal::tests` for directory validity, command arguments, and path quoting. AppleScript compilation does not execute terminals or prove session reuse, authorization, or successful Agent startup.
