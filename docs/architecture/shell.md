# Shared app shell

`oneo-gpui` is the reusable core shell for ONEO apps, independent of Locus product types. `src/lib.rs` declares modules and collects public exports. Files such as `app.rs` and `window.rs` each own one responsibility; matching directories hold only internal implementations. Rust directories do not automatically create modules. Parents declare submodules with `mod` and selectively expose interfaces with `pub use`. Existing workspace, settings, and button components retain their responsibilities without forwarding-only layers created for directory symmetry.

- `src/app.rs` and `src/app/menu.rs`: `AppShell` manages the GPUI platform app, default icon assets, component initialization, reduced motion, generic shortcuts and quit/close/fullscreen actions, and main-window reactivation. Menus accept product labels and items.
- `src/window.rs` and `src/window/`: `ShellWindow` creates windows and a single `Root`, handling restoration, titlebar geometry, macOS Sidebar material, and platform close behavior.
- `src/config.rs`: `SettingsStore` resolves project paths, reads generic TOML, atomically replaces files, and creates without overwriting. It does not own runtime preference entities.
- `src/workspace.rs` and `src/settings.rs`: sidebar and layout state, settings mode, sidebar settings buttons, and generic settings presentation.
- `src/appearance.rs` and `src/appearance/`: shared appearance configuration, theme and system-language resolution, interface font size, controlled selectors, and native window appearance.
- `src/button.rs`: toolbar buttons.

`AppShell::new().run(...)` initializes components, platform reduced-motion behavior, and shell Actions before product initialization. The callback loads product configuration, registers capabilities, and returns the main-window handle. Startup errors include their causes, print to standard error, and exit. System app reopening activates the main window; close and fullscreen affect the active window. On macOS, Release closing hides and retains the window, while Debug closing exits. Other platforms remove Release windows on close. Apps can replace the complete asset source through `with_assets`; sidebar and settings shortcuts remain available. Locus's `src/assets.rs` combines the default component assets with explicitly embedded Download, Pencil, and Info icons. Icons outside the default subset must be registered there, not only referenced by their catalog enum; app asset tests verify their listings and SVG data.

Each window uses `gpui_kit::open_window` to create one `gpui_kit::base::Root`; `gpui_kit::component::Root` re-exports that type. Component initialization registers a per-window presentation plugin, which automatically hosts sheets, dialogs, and notifications. Product views render their content and custom overlays without adding those framework layers themselves. ShellWindow keeps its typed Root handle and applies a transparent root background after creation. Interface base font size enters Theme and synchronizes Base projection; Root sets window rem. Layout scales from that baseline, and theme/system appearance changes preserve user font size. Locus's sidebar and note page use GPUI cached View boundaries.

## Debug frame rate

`WorkspaceSidebar` mounts the debug-only FPS control at the bottom-left before caller-provided bottom content and the settings button. It uses a compact outlined container whose height follows its number and padding and is vertically centered. Button padding is 0.25 rem, corners use theme radius_lg, and the outline uses sidebar_foreground at 10% opacity. Numbers use 0.625 rem and muted_foreground. Hover changes only the inner background. Release creates neither the statistics entity nor its layout. Locus, Theme Smith, Opus Index, and the shared-shell example use the sidebar entry point; content titlebars do not display FPS.

`oneo-gpui/src/fps.rs` uses GPUI `FrameTimingCollector`. Current FPS counts Present events from the window's last second, samples every 250 ms, notifies only on value changes, starts at 0, and requests no animation frames. MAX retains durations for the latest 120 Draw events, estimates FPS by dividing count by total duration, and rounds. It is not a historical peak. The estimate is capped at the current display's refresh rate and the result rounded. macOS uses CoreGraphics display modes; Windows uses GDI display settings. Sampling rereads them to follow display or refresh-rate changes. If the system reports no valid fixed refresh rate, the duration estimate remains without a guessed cap. Platform queries reuse locked `core-graphics` and `windows` dependencies. No samples or zero total duration display 0; no new draws preserve the last estimate.

The control displays one number, defaulting to maximum FPS when created. Its outer container retains a stable outline; a standard Ghost Button provides inner background feedback, and the number explicitly sets size and color. Click, Enter, or Space toggles current/maximum mode without sampling resetting the choice. Mode is not persisted; rebuilding defaults to maximum. English and Chinese tooltips and accessible names describe the mode and switch result. The hit region isolates titlebar dragging and retains standard keyboard focus. Real commits caused by refreshing the display count toward FPS. Window keyed state owns the statistics entity; leaving the sidebar render tree releases it and its timer, and returning starts new sampling. Debug startup enables process-level frame tracking, using framework tracing without another performance overlay.

## Windows and layout

`ShellWindow::new(title)` defaults to 980 × 820 initial and 640 × 480 minimum logical pixels. Apps set constraints through `with_size`, `with_min_size`, and `with_saved_bounds`; Locus uses `locus-preferences::config`. Restoration requires at least 120 × 24 logical pixels of titlebar within one display's usable area; otherwise the window centers at its initial size. `ShellWindow::min_size()` reads the configured minimum. The Kit window entry point wraps `Root` once; caller entities own product content and focus, and product interface state owns persistence.

`WorkspaceShellConfig` and `AppShellState` configure sidebar and main content. Sidebar initial and minimum widths are 252 logical pixels, maximum 420; center content minimum is 360. `WorkspaceShell` supplies an always-visible sidebar toggle, platform titlebar position, and divider; callers handle shared panel Actions. Shared tool buttons isolate their hit areas, so click, drag, and double-click do not move or resize the underlying window, even when disabled. `toolbar_dropdown_menu` isolates hits in its outer wrapper while retaining its internal trigger. Sidebar and settings entry points cannot be closed. `WorkspaceSidebar` supplies a draggable titlebar and bottom-right settings button, with slots at titlebar right, content, and bottom left. Bottom padding is 0.5 rem on every side. Sidebar content adds no extra top spacing, using existing macOS titlebar bottom spacing. `WorkspacePanel` supplies expanding content and optional titlebar/footer. Titlebars are 48 logical pixels high with semibold text. Default panel interface text uses `text_sm` (14 at base size 16), scaling with global font size; body content may override it.

Locus defines product window and sidebar sizes in `locus-preferences::config`, using the same configuration for initialization and divider reset. See [Desktop workspace](workspace.md) for dimensions and behavior. The shared shell handles collapse and resizing without changing native window width.

`SettingsShell::appearance` supplies complete theme, language, and font-size groups and navigation; callers append only business settings. `AppearanceControls` retains control state while products own configuration saving and notifications. On macOS and Windows, `SettingsShell` keeps its root and sidebar transparent, revealing the app root's shared `workspace_background` and native material. Settings content remains an opaque semantic surface. Locus and Theme Smith reuse this behavior without overriding sidebar backgrounds. Settings sidebar width is fixed at 252 logical pixels. The return entry below the platform titlebar reuses settings-navigation text, icon, hover, and focus styles and dispatches `CloseSettings`; callers restore focus. Content retains a blank draggable 48 px titlebar without a page title. `SettingsGroup` supplies category titles and rounded containers, with 0.75 rem title left padding and 13/16 rem radius. `SettingsItem` supplies a title, optional description, and custom trailing control, with 0.125 rem title/description spacing, 1.125 rem title line height, and 1 rem description line height. Products supply categories and contents without recreating default buttons, rows, or group containers.

## Standalone example

`source/crates/oneo-gpui/examples/minimal.rs` runs through `cargo run -p oneo-gpui --example minimal`. It demonstrates project names, TOML types, app startup, and sidebar/main-content workspace composition without Locus dependencies. The sidebar starts expanded; both regions have draggable titlebars. Buttons and shared shortcuts collapse it, divider drags resize it, and divider double-click restores initial width. The example reuses shared layout state without persisting sidebar state. The bottom settings button and Command+, open the same inline settings page; returning preserves panel state and restores workspace focus. Appearance changes apply immediately and save to `~/.oneo/oneo-example/settings.toml`, with save errors in settings. Example copy lives independently in `examples/locales/ui.yml`.

## Platform and native behavior

Non-Debug Windows Locus builds use the GUI subsystem without a launch console; Debug retains one. `locus-library/src/process_environment.rs` sets `CREATE_NO_WINDOW` on background Git commands; `locus-ui/src/platform.rs` applies it to VS Code launches, preventing console flashes while retaining output capture. Explicit external Agent launches still create consoles through the terminal module; see [Library terminal](terminal.md).

On macOS, GPUI's full-window blur view hosts system Sidebar material. The GPUI root remains transparent; the app owns neutral tinting and opaque content surfaces. On Windows, shared ShellWindow calls `window.set_background_appearance(WindowBackgroundAppearance::MicaBackdrop)` during creation. GPUI synchronizes native material and rendering state, without app-side capability detection or Blur fallback. Platform modules keep light/dark material synchronized. Shared workspace background is transparent on Windows; Locus settings roots, shared settings roots, and sidebars avoid opaque fills, while main content uses opaque semantic surfaces. Existing windows 0.58 and raw-window-handle dependencies enable only DWM and window-operation features, without new packages. Platform-specific implementations stay in platform modules and the shared shell, not product domains depending directly on AppKit or Win32. Shared content_titlebar combines business titles with Windows controls using WindowControlArea for native hit testing; settings reuses it. See [Desktop workspace](workspace.md) for product page composition.

The shared neutral macOS sidebar tint uses alpha 0.85 in both themes. Main content, settings content, and overlays use opaque semantic surfaces, while GPUI ancestors of canvases stay transparent.

Windows workspace and settings titlebars place minimize, maximize/restore, and close controls on the right. Compact square buttons use theme radii, vertical centering, and equal top, bottom, and right clearance. Maximized windows show restore icons; keyboard activation uses the same Actions. Close hover uses a red background and white icon, with darker red when pressed. WindowControlArea supplies native hit regions alongside business titles and toolbars.

The settings return entry avoids macOS traffic lights. Windows uses 0.75 rem top spacing matching side spacing, while content retains a draggable titlebar and window controls. Window drag regions and button hits remain separate, preserving keyboard paths and focus feedback on all platforms.

Native Mica availability and appearance depend on GPUI, OS version, DWM, and system transparency policy. The app calls the framework API, synchronizes themes, and accepts unsupported-platform behavior without product-level capability detection or fallback state machines.

Native material is a window environment layer; main content and overlays use stable semantic surfaces. AppKit effect views sit outside GPUI's rendering surface and cannot be inserted between draws on the same Metal surface, so menus and content backplates do not depend on local background blur. Panel collapse clips complete content, and reduced-motion settings apply layout directly.

## Verification boundaries

Shared-shell changes require its own tests and compilation/integration checks for affected consuming apps. Sidebar dragging uses production window-level listeners; regressions cover crossing occluded regions, release, and no further width changes afterward. Tool buttons require pointer and keyboard checks and titlebar hit isolation. The window-host regression opens an interactive dialog through `WindowExt` and verifies rendering and click delivery without manual overlay layers.

Platform materials, window controls, system reactivation, display changes for FPS, and refresh-rate caps need confirmation on the relevant platform. macOS checks or simulated Windows layout do not establish compilation or execution of native Windows branches. See [Settings and persistence](settings.md) for configuration and appearance-resource contracts.
