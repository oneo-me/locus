# Agent 接入

本篇维护当前行为、实现边界与验收要求。需求编号见[需求索引](../requirements.md)。

## 目标与入口

外部客户端可使用标准接口发现原始文件，也可只通过完整接口操作当前文档库。两个入口共享真实文件，不建立内容数据库或托管副本；Locus 不拥有 Agent loop、模型调用、客户端执行权限或通用文件系统工具。

同一 Streamable HTTP 服务提供 `/mcp` 与 `/mcp/full`，共用端口、文档库、启停和局域网设置。标准接口保留已有契约；完整接口的发现、内容读取、写入与传输均不依赖客户端访问服务端磁盘。

## 标准接口

`/mcp` 暴露三个只读工具：

- `list_articles`：`parent` 接受父级库内相对路径或 `locus://` 地址，分页列出直接子笔记；空值或 `locus://` 浏览库根。
- `search_articles`：在库内路径、标题、概要、附件名和正文中执行不区分大小写的包含检索，并返回有限正文摘要。
- `resolve_article`：`path` 接受已知库内相对路径或 `locus://` 地址，两种形式均接受末尾 `/index.md`；库根不可解析为笔记。拒绝空段、`.`、`..` 和越界路径。

结果继续包含元数据、用于层级导航的库内路径以及文件和目录绝对路径。客户端使用自身文件工具维护内容。标准接口保留 `path` 与 `parent` 参数名，不使用 `uri` 参数；工具说明及参数 schema 明确地址写法。`locus://` 地址复用共享解析器，百分号编码仅解码一次，拒绝编码后的越界片段、分隔符、空字节和无效 UTF-8；查询与片段不作为地址接受，名称中的井号须编码。普通相对路径保持字面值，不进行百分号解码。

## 内置软件规范

附件与画布使用规范以英文 Markdown 随软件维护与打包。两个 MCP 入口均声明 Resources 能力：`resources/list` 返回 `locus-docs://attachments` 与 `locus-docs://canvas` 的名称、说明、`text/markdown` 类型和字节数；`resources/read` 返回对应完整正文。初始化指令要求 Agent 在编写对应内容前读取规范。

资源地址独立于 `locus://` 笔记命名空间，不传给笔记工具，也不参与笔记搜索、导航或内容修改。没有选择笔记库时仍可读取；库内内容不能覆盖软件规范。未知地址或试图访问路径返回资源不存在错误；固定清单无后续分页，提供游标返回参数错误。软件规范跟随正在运行的应用版本，不提供订阅或写入接口。

共享模版由各文档库自行组织，软件不预设模版目录或清单。

## 完整接口

`/mcp/full` 使用 `locus://<库内逻辑地址>` 标识笔记或组织目录，浏览根为 `locus://`。内容目标由笔记地址与 `note`、`canvas`、`icon`、带相对文件路径的 `canvas_file` 或带文件名的 `attachment` 资源组成。地址中的空格、百分号和井号采用百分号编码，完整接口、桌面导航和画布组件统一解码一次并拒绝编码后的越界片段。服务端负责映射磁盘文件，结果和错误不生成本机绝对路径、`file://` 地址或要求客户端直接编辑磁盘的提示。用户原文与自定义元数据中的路径属于内容，读取时保留。

- `list_entries`、`search_notes`、`resolve_entry`：分页浏览与搜索，包含显式归档笔记及其后代和无正文组织目录；读取当前元数据与所属资源。
- `create_directory`、`create_note`：在现有父目录下创建对象；组织目录可增加正文，保留后代，不覆盖已有正文。
- `read_text`、`write_text`、`patch_text`：读取完整原始 UTF-8 文本及版本，按行分段；覆盖或执行唯一精确匹配替换。正文及自定义 frontmatter 可通过相同工具编辑。
- `set_archived`：设置归档或恢复，保留无关元数据、正文和换行风格。
- `stat_content`、`download_chunk`：获取内容版本和大小，分块下载完整字节。
- `begin_upload`、`upload_chunk`、`finish_upload`、`cancel_upload`：暂存、校验、提交或取消上传，支持文本、图片与任意普通二进制附件。
- `delete_content`：永久删除指定正文、画布、图标或附件，不删除同目录其他内容；图标删除同步清空元数据引用。只删除正文后，需重新建立正文才能继续按笔记访问保留资源。
- `plan_move`、`move_entry`：预览并重命名或移动整个笔记/组织目录，携带后代、附件和画布，处理可确定的 Markdown 链接。
- `move_attachment`：附件独立重命名或跨笔记移动，不覆盖目标；更新可识别的 Markdown 链接并返回受影响笔记，画布和脚本引用由客户端显式检查。
- `inspect_tree`、`delete_entry`：获取范围与版本，删除空目录或按明确递归参数永久删除整棵笔记子树。
- `export_manifest`：列出子树目录与内容版本；结合下载、创建和上传工具完成导出与重建。

`note` 对应 `index.md`，`canvas` 对应 `canvas/index.html`，`canvas_file` 对应画布目录中的其他文件（含 main.js、index.json、CSS 和数据文件）并允许嵌套路径；`icon` 对应 `assets/icon.png`，`attachment` 对应 `assets/<name>`。资源目录按写入需要建立，符号链接不能作为目录或文件。`assets`、`canvas` 不允许作为笔记或组织目录，也不计入子笔记数量。

画布继续遵循[文档库](library.md)的唯一所属画布、资源目录及运行边界。普通画布为 HTML 片段与 main.js 入口；跨笔记整页复用通过 index.json 的 template 与 data 完成。node_modules 为安装产物，不通过内容接口读写或导出。编写规则见 `locus-docs://canvas`；规范分别说明标准与完整接口的编辑方式。

## 传输与失败恢复

上传提交前不改变目标文件。初始化上传指定解码后的总大小、预期目标版本，可提供 SHA-256；分块使用 base64，按已接收偏移顺序写入，相同字节的重复分块可重试。完成时必须验证总大小及已提供的校验值，并重新检查目标版本。未完成、校验失败、取消或过期不得留下可见的半成品附件。

每块最多 256 KiB；单会话最多四个待提交上传，总声明大小最多 1 GiB。上传空闲十分钟失效，下次调用清理；会话或服务释放时回收暂存文件。笔记与画布上传最多 8 MiB。图标沿用现有图片归一化：来源最多 16 MiB，按比例生成不超过 64 × 64 的 PNG 并同步笔记元数据；提交结果区分原始上传校验值与生成后图标版本。

下载先取得大小及版本，再按偏移读取字节，默认每块 64 KiB、最多 256 KiB，返回后续偏移及结束标识。客户端解码并保存文件；文件变化时失败，不能拼接不同版本。客户端需要能够提供上传字节和保存下载字节，但无需访问服务端文件路径。

文本读取使用从零开始的行偏移，默认 200 行、最多 2000 行，并返回全文版本、总行数与后续行号。直接文本读写最多 8 MiB，已有更大文件通过字节下载读取。

子树导出先读取清单，再按每项版本下载。导入按父目录优先创建目录及笔记，再写入画布和附件；图标遵循归一化规则。完成后重新导出核对内容版本，识别导出或导入期间的变化。该流程全部使用完整 MCP 接口，不另建下载服务。

## 变更与冲突

内容版本使用 SHA-256。更新、覆盖、删除携带读取时的 `expected_version`；创建使用 `missing`，已存在对象不得隐式覆盖。精确补丁的旧文本必须非空且唯一匹配。冲突返回可见错误，客户端重新读取并合并后重试。

完整接口调用在服务的文档库操作所有者中串行执行。文件写入暂存完整内容，提交前再次检查版本，再替换目标；这提供外部编辑器的乐观冲突检查，不代表外部编辑器参与了文件锁或跨文件事务。多文件操作不承诺进程崩溃后的原子回滚。

`plan_move` 返回来源子树与受影响笔记版本组成的操作版本，`move_entry` 校验后执行。修改标题使用元数据编辑；重命名和移动改变逻辑地址及目录。可识别的 Markdown 内联/引用式链接随移动更新，包含外部入链和被移动笔记的相对出链，正文代码与 frontmatter 保留。画布 HTML、脚本、自定义元数据及动态拼接引用不猜测改写，结果提示客户端检查并显式编辑。目录移动使用不覆盖已有目标的原生重命名；附件移动同样更新可确定的 Markdown 链接并返回受影响笔记。普通执行失败尝试回滚，回滚不完整返回 `partial_failure` 并要求检查两个地址及受影响笔记。

`delete_entry` 需要 `inspect_tree` 的当前子树版本；默认非递归，只删除空目录，显式 `recursive=true` 删除整个目标。库根不能删除或重命名。隐藏、排除或非普通条目阻止整树移动与删除，避免把未管理数据隐式包含到破坏范围。删除不自动删除其他笔记中的入链。

## 监听与生命周期

- 服务默认关闭，默认端口 `2301`；本机模式绑定 `127.0.0.1`，局域网模式绑定 `0.0.0.0`。
- 两个入口共同使用现有局域网开关，无独立认证流程。启用前说明局域网客户端可以读取、上传、修改和永久删除文档库内容，标准接口还返回绝对路径。
- 两个入口共同限制 Host：允许 localhost、回环地址及每条 TCP 连接实际接收请求的本机 IP；拒绝任意其他主机名和无关 IP。不枚举网卡，不选择或展示局域网地址。
- 未配置库、无效地址、越界、符号链接、缺失资源和读取失败返回真实错误；不能返回虚构空结果或暴露服务器路径。
- 配置变化先停止旧服务，再按新配置启动；退出释放服务。旧会话与上传不能跨服务重启或文档库切换复用，停止后排队的操作不得写入新库。
- 设置保留服务开关、局域网开关、端口与真实运行状态，启动失败显示原因。客户端按端口和既定路径自行配置，连接说明由使用文档提供。侧边栏左下角只显示不可点击的 MCP 图标，不显示常驻文字；运行时使用绿色 success、失败时使用红色 danger、停止时使用灰色 muted_foreground。悬停提示和无障碍名称表达具体状态，不占用键盘操作焦点。标准与完整接口继续同时提供，客户端按端口和既定路径自行配置。

## 工程与验收边界

`locus-library::LibraryAccess` 拥有逻辑地址、文件操作、版本检查和链接处理；标准 MCP 工具维持独立契约，完整工具与上传会话属于 `locus-mcp`，监听与停止控制由同一控制器持有。两者不依赖工作区选中项或导航缓存。模块依赖见[架构总览](../../ARCHITECTURE.md)。

验收要求：标准接口三工具和返回结构保持一致；客户端只通过完整接口完成创建、读取、编辑、上传、下载、归档恢复、重命名、移动和删除；二进制下载与来源一致；图标被当前笔记消费者识别；画布及其资源能被既有画布读取；清单可重建笔记子树；冲突、中断、错误校验、越界和旧会话不能产生错误写入；两个地址共享本机及局域网生命周期和 Host 限制。设置实际体验、真实跨设备连接与画布视觉效果由用户验证，不能用本机协议测试替代。

## 服务实现

`locus-mcp/src/lib.rs` 在每条连接的 Axum Router 中挂载标准和完整服务；服务克隆共享各自的会话管理器和文档库操作锁。通过 TCP 连接的 `local_addr` 取得接收请求的本机 IP，与 localhost 及回环地址一起交给 rmcp 进行 Host 校验，不枚举网卡或维护局域网地址缓存。MCP 包禁止 `unsafe`，不直接依赖 `libc`；直接引用锁文件已有的 `tower`，使用 `service_fn` 组装连接服务，不自行实现 Host 解析或校验。`service.rs` 保留标准契约；`full.rs` 适配完整工具并把阻塞文件工作放入 Tokio blocking 任务，所有完整会话共用一个文档库操作锁。`full/transfer.rs` 持有会话内暂存上传，服务关闭或会话释放回收文件；取消令牌防止停止后的排队请求执行。

工作区将设置显式映射为 `McpConfiguration`，只传入文档库路径、启用状态、监听范围和端口。控制器不读取偏好存储，设置通过 `SettingsEvent` 通知工作区。

## 内置软件文档资源

`source/resources/docs/attachments.md` 与 `source/resources/docs/canvas.md` 是随软件维护的英文使用规范。`source/crates/locus-mcp/src/docs.rs` 持有固定资源清单，通过 `include_str!` 引入同一源文件，两个服务共用发现与读取实现，不依赖文档库路径、GUI 或客户端文件访问。规范随二进制版本更新，不增加运行期缓存、路径查找或回退逻辑。

`source/packer.toml` 将源码目录内的 `resources/docs` 映射到打包资源目录的 `docs`：macOS 为 `Contents/Resources/docs`，Windows 便携目录为 `resources/docs`。正文由同一源文件同时提供编译期内容与可读取的打包文件。资源发现与读取契约见本篇的“内置软件规范”。

## 验证方法

使用 `cargo test -p locus-library -p locus-mcp --locked -- --test-threads=1` 检查逻辑地址、文件操作及 HTTP 契约；HTTP 测试需允许本机临时端口监听。既有测试存在服务停止后重绑端口的 `AddrInUse` 风险，串行运行可减少并发干扰。

资源回归还需运行 `oneo-tool-packer` 测试，核对两个入口在未选择文档库时均能读取完整协议，以及 macOS、Windows 资源复制结果与同一源文件逐字节一致。协议测试不代替跨设备连接、设置体验或实际应用打包验收。
